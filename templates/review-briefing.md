# 리뷰 브리핑

[범위를 제한한 단계별 검토 자료](../docs/review-gates.md)를 위한 선택적 양식입니다. 작업에 필요한 내용만 작성하며 작업 항목 댓글에 같은 정보를 담아도 됩니다. 새로 작성한 템플릿이며 실제 수행한 검토 기록이 아닙니다. 필요한 경우 단계별 판정을 구분합니다.

## 전체 브리핑 — 다섯 절

```text
1. 작업과 검토 대상
   작업 항목 / 계약 리비전:
   단계: AS-IS | PLAN | CODE
   정확한 후보 / 스냅샷:
   AC 참조와 구체적인 검토 질문:

2. 확정된 계약
   승인된 선행 결정과 증거:
   직접 계약 / 불변 조건 / 보존할 동작:
   관련 정책 참조와 버전:

3. 경계와 읽기 시작점
   수정 허용 / 금지 범위:
   직접 경로, 심볼, 호출자·피호출자:
   제외 범위와 사유:

4. 증거와 불확실성
   후보·환경이 연결된 AC별 증거 참조:
   실제 관찰, 미실행 검사, 차단 사항:
   알려진 미확인 사항과 회귀 우려:

5. 요청하는 응답
   검토자 식별값·세션과 단계·후보:
   판정: PASS | CHANGES_REQUIRED | BLOCKED
   지적사항: 유형, 위치, 증거, 위반한 AC·계약, 필요한 수정
   미확인 사항 / 검토하지 않은 범위:
```

원본 증거에 접근할 수 있어야 합니다. 읽기 시작점은 주장을 확인하는 데 필요한 의존 관계를 읽지 말라는 제한이 아닙니다. 읽기를 넓혀도 수정 권한이 넓어지지는 않습니다. PASS는 사람의 승인이나 미실행 검사에 대한 증거가 아닙니다.

## 지적 수정 후 축약 브리핑

이전 브리핑에 접근할 수 있고 변경되지 않은 문맥이 계속 유효할 때만 사용합니다. 새 검토자도 주장을 평가할 수 있는 원래 문맥을 충분히 받아야 하며, 필요하면 브리핑을 확장합니다.

```text
이전 브리핑 / 단계 / 검토한 후보 / 지적사항 참조:
새 후보 / 현재 작업 항목 계약 리비전:
변경된 입력과 동일성 비교 증거(사용한 경우):

지적사항 -> 수정 -> 변경 위치 -> 검증 증거:
영향받는 AC·의존 관계와 재실행한 회귀 검사:
재사용한 증거와 계속 유효한 이유:
잔여 지적 / 미검증 사항 / 변경된 경계나 결정:

검토 질문: 현재 AC, 확정된 계약, 수정 경계를 위반하지 않으면서
인용한 지적사항을 해결했는가?
기존 검토 결과 계약에 따라 검토자 식별값, 단계·새 후보, 판정,
지적사항, 남은 미확인 사항을 반환한다.
```

이전 PASS를 새 후보에 대한 판정으로 제시하지 않습니다. 중요한 계약 변경은 개별 수정 여부만 확인하는 것으로 끝내지 않고 영향받는 단계를 다시 검토합니다.

선택적 Blind Audit에서는 감사자가 독립적인 최초 결과를 확정하기 전에 수정 브리핑이나 이전 판정·지적사항을 전달하지 않습니다. 현재 AC, 계약, 후보, 안전 경계를 담은 새 전체 브리핑을 만들되 이전 검토의 결론을 유도하는 설명은 제외하고, 이후 결과를 대조합니다.
