# 사람 실행 검증 인계

**DRAFT / OPTIONAL.** [제한 환경 검증 절차](../docs/restricted-environment-verification.md)를 위한 양식이며 실행 허가나 검증된 자동화가 아닙니다. placeholder는 승인된 로컬 환경에서 채웁니다. 민감한 입력이나 원본 출력을 공개하지 않습니다.

## 검증 계획자가 준비하는 내용

- 작업 항목 / 기준 AC 리비전:
- 후보 / 환경 / 테스트 입력 식별값:
- 허가된 실행자와 허용 작업:
- 사전 조건, 검토된 단계·요청·쿼리, 제한, 부작용, 중단 조건:
- 안전한 증거 저장 위치와 필요한 관찰:

| TC ID | AC 참조 | 입력·단계 참조 | 실행 전에 고정한 기대 관찰 | 요구사항 출처 |
| --- | --- | --- | --- | --- |
| TC-01 | AC-01 | | | |

관련 경계값과 실패 동작을 포함해 TC가 필수 AC를 실제로 입증하는지 확인합니다. AC와 TC는 일대일일 필요가 없습니다. 계획 검토는 실행 증거가 아닙니다.

## 실행자가 반환하는 내용 — 관찰 결과, PASS 판정은 요구하지 않음

- 실제 실행한 후보 / 환경 / 입력 식별값:
- 실행자 / 실행 시각:
- 준비된 단계와 다르게 수행한 내용:

| TC ID | 실제 값·관찰한 동작 | 실행 오류 또는 장애 | 비식별화된 증거 참조 |
| --- | --- | --- | --- |
| TC-01 | 실행하지 않음 | | |

오류, 부분 출력, 실행하지 못한 사실도 관찰로 반환합니다. 준비된 기대값은 확인할 수 있게 유지하되 결과에 맞춰 수정하지 않습니다. 관찰 수집과 판정을 분리하는 것이며, 실행 단계나 안전 정보를 실행자에게 숨기는 것이 아닙니다.

## 증거를 받은 뒤 평가자가 작성하는 내용

| AC·TC | 기대값·계획 리비전 | 실제 관찰 참조 | 후보·환경 | 상태 | 사유·누락 증거·다음 조치 |
| --- | --- | --- | --- | --- | --- |
| AC-01 / TC-01 | | | | UNVERIFIED | 아직 실행 증거가 없음 |

[검증 상태](../docs/verification.md)를 사용합니다. 실제 실행 대상이 요청한 후보와 일치하는지, 증거가 각 AC를 입증하기에 충분한지 확인합니다. 요청 성공만으로 이후 효과까지 입증되지는 않습니다. 구체적인 실행 장애는 BLOCKED, 누락되거나 불충분한 증거는 UNVERIFIED입니다.

## 정정·재실행 이력 — 필요한 경우

| AC·TC | 이전 기대값·관찰·판정 참조 | 변경 내용과 기준 출처에 따른 사유 | 필요한 결정·수정 계약 참조 | 영향받는 검사·새 후보·새 증거 |
| --- | --- | --- | --- | --- |
| | | | | |

기존 관찰과 판정을 보존합니다. AC를 유지한 채 TC를 정정하는 경우와 AC 자체를 바꾸는 경우를 구분합니다. 기존 증거가 충분한지 또는 어떤 검사를 다시 실행해야 하는지 기록하며, 코드가 바뀌면 영향받는 검사를 새로 실행합니다. 이전 결과는 원래 후보에 연결해 둡니다. TC를 행정적으로 종료해도 미충족 필수 AC가 충족되지는 않습니다.
