# Large 예시

**가상 변경:** 외부 유료 작업 전에 재시도 예산을 강제합니다.

재시도 의미, 비용 노출, 큰 실패 비용 때문에 Large입니다. 실제 provider, endpoint, 스키마, 고객, 운영 결과는 포함하지 않습니다.

## 순서가 있는 게이트

1. AC, 보존할 동작, 수정 허용·금지 경계, 확정된 결정을 정의합니다.
2. 현재 코드·증거에서 AS-IS를 작성합니다. 재시도 책임과 외부 호출 경계를 확인하고 미확인 사항을 표시합니다.
3. 해당 리비전에 대한 **독립 AS-IS 판정**을 받습니다. 분석을 PLAN 기준으로 삼기 전에 관찰·계약 차단 사항을 해결합니다.
4. TO-BE·변경 계획을 작성합니다. 재시도 차수 입력, 누적 비용 입력, 허용·차단 결정, 실패 처리, 제한 적용 순서를 정의합니다. 실제 트레이드오프가 있을 때만 기록합니다.
5. TO-BE·변경 계획 리비전에 대한 별도의 **독립 PLAN 판정**을 받습니다. 사람이 소유한 결정은 필요한 승인을 받습니다. AS-IS PASS나 검토 PASS가 그 승인을 대신하지 않습니다.
6. 허가된 범위를 구현하고 대상·최종 증거를 수집하며 관련 지속 문서를 동기화합니다.
7. 최종 후보의 독립 **CODE 검토**를 받습니다. 명시된 누락·편향 위험이 있을 때만 Blind Audit을 추가하고 결과 대조 전에 최초 판정을 보존합니다.
8. 필요한 통합·런타임 관찰을 수집합니다. 필수 증거가 없거나 실패하면 준비 완료를 차단합니다.
9. 최종 후보와 요청 행위를 제시하고 사람의 허가를 받은 뒤 허가된 병합·종료·정리만 수행합니다. 릴리스가 포함되지 않았다면 별도 권한이 필요합니다.

같은 독립 Reviewer가 AS-IS와 PLAN을 맡아도 판정은 구분합니다. 직접 호출자·계약은 읽을 수 있지만 범위 밖 수정은 허용하지 않습니다.

## 검증 계획 예시 — 실행하지 않음

| AC ID | 기대 증거 | 이 예시의 상태 |
| --- | --- | --- |
| AC-01 | 한도 직전·한도 도달·한도 초과의 결정이 승인된 예산 계약과 일치 | UNVERIFIED |
| AC-02 | 재시도 누적이 승인된 계약을 따름 | UNVERIFIED |
| AC-03 | 차단 결정 시 유료 작업이 발생하지 않음 | UNVERIFIED |
| AC-04 | 필수 입력이 없을 때 승인된 실패 동작을 보존 | UNVERIFIED |

제안된 검사이지 입증이 아닙니다. 필요한 런타임 환경이나 독립 Reviewer가 없으면 PASS를 흉내 내지 말고 차단 사항을 보고합니다. 후보의 중요한 변경 후에는 영향받는 검증·검토·승인을 다시 수행합니다.
