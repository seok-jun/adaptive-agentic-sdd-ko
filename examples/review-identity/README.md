# 리뷰 대상 동일성 확인

**OPTIONAL / FICTIONAL — 구현 절차를 설명하는 가상 예시이며 제공된 수집 도구나 런타임 강제 기능이 아닙니다.** 증거와 승인의 유효 조건은 [검토 정책](../../docs/review-gates.md)이 정의합니다. 후보 전체를 식별할 수 있다면 커밋이나 다른 명확한 스냅샷으로 충분합니다. 이 예시는 미커밋 변경이 있는 worktree와 외부 작업 항목을 함께 검토할 때 유용합니다.

## 검토한 입력을 보존하기

다음을 변경할 수 없는 로컬 보존 기록으로 남깁니다.

| 구분 | 내용 |
| --- | --- |
| 식별 정보 | 검토 단계, 저장소, HEAD, 고정된 비교 기준 리비전, 수집 시간, 스냅샷 형식 버전 |
| 포함 범위 | 포함 경로·직접 의존 관계, 제외 대상과 사유, 후보 선택 규칙 |
| 실제 후보 파일 | 정렬된 경로, 존재·삭제 여부, 실제 내용의 해시, 관련 파일 모드 또는 링크 대상 |
| 작업 항목 계약 | 기준 작업 항목 리비전 또는 고정된 내보내기 사본, AC, 범위, 확정 결정, 수정 경계, 적용 정책 버전 |
| 증거 문맥 | 검증 증거 참조, 테스트 입력, 관련 환경·설정 식별값 |

Reviewer가 실제로 읽는 후보를 수집합니다. staged·unstaged 변경, 추적 파일의 삭제, 관련된 비무시 미추적 파일을 목록에 포함합니다. 고정된 기준 리비전과 현재 후보의 경로 합집합을 비교해서 삭제된 경로도 부재 상태로 남깁니다. 주장에 영향을 주는 의존 관계와 명시적으로 승인된 무시 파일 입력도 포함하되, 무시 파일이나 비밀값을 무차별 수집하지 않습니다.

이 예시에서 `files`는 기록된 범위 안의 실제 내용·존재 여부·모드를 식별하며 staging 상태 이름은 포함하지 않습니다. 검토한 파일을 내용 변경 없이 커밋하면 추적·staging 상태는 달라져도 실제 후보는 같을 수 있습니다. Git 상태 목록은 별도로 보존하고 최종 커밋과 후보를 대조합니다. staged 파일만 커밋하면 검토했던 unstaged·미추적 내용이 빠질 수 있습니다.

작업 항목 사본은 출처 참조가 있는 이력 증거로 보존하며, 별도로 수정하는 요구사항 기준을 만들지 않습니다. URL이나 이슈 번호만으로는 내용을 고정할 수 없습니다. 해시와 함께 원래 입력도 다시 확인할 수 있게 남깁니다. 해시만으로 누락된 계약을 설명할 수는 없습니다. 수집이 불완전하거나 일관되지 않거나 수집 도중 내용이 바뀌면 거부하고, 누락을 동일함으로 처리하지 않습니다.

## 완전한 스냅샷 두 개 비교하기

설명용 의사 코드입니다. `same`은 일관된 형식으로 직렬화한 전체 필드 또는 그 해시를 비교합니다.

```text
require complete_and_consistent(reviewed, current)
require same_repository(reviewed, current)

inputs = [phase, base, format, coverage, candidate_selection,
          files, work_item_contract, evidence_context]

if any input differs:
    return changed
if reviewed.HEAD != current.HEAD:
    return head-only
return identical
```

수집 시간과 관리용 상태 이름은 출처 정보이며 내용 동일성의 기준이 아닙니다. 필드 누락, 입력 읽기 실패, 비교 오류가 발생하면 세 가지 정상 결과 중 하나를 내지 않고 비교를 중단합니다. 영향받는 판정을 재사용하기 전에 누락을 보고하고 해결합니다. `identical`로 표시하지 않습니다.

| 결과 | 의미 | 후속 처리 |
| --- | --- | --- |
| `identical` | HEAD와 비교한 검토 입력이 모두 동일함 | 원래 검토 범위 안에서만 재사용합니다. AC 입증이나 권한 부여를 뜻하지 않습니다 |
| `head-only` | HEAD가 다르지만 비교한 검토 입력은 모두 동일함 | 이전·새 후보 대응을 기록하고 최종 커밋 내용과 증거의 유효성을 확인한 뒤 새 후보에 기존 승인 정책을 적용합니다 |
| `changed` | 검토 입력 중 하나 이상이 달라짐 | 영향을 분석하고 필요한 증거·검토·승인을 갱신합니다. 모든 검사를 자동으로 반복하지 않습니다 |

이는 비교 결과이며 검토 판정이나 검증 상태가 아닙니다. `head-only`는 승인을 자동 승계하지 않습니다. 빌드에 커밋 ID가 포함되거나 환경이 달라졌다면 파일 내용이 같아도 런타임 증거의 동등성을 보장하지 못합니다. 범위 밖 변경이 검토한 의존 관계에 영향을 주면 포함 범위를 넓히며, 해당 경로를 제외해서 변경을 숨기지 않습니다.

## 정적 진행 예시 — 실행한 테스트가 아님

- 수집 시간을 제외한 스냅샷이 같음: `identical`.
- 검토한 미추적 파일을 같은 내용으로 커밋했고 나머지 입력도 같음: `head-only`. 최종 커밋이 후보 전체를 포함하는지는 여전히 확인합니다.
- HEAD는 같지만 unstaged 파일이나 이슈 AC가 바뀜: `changed`.
- 추적 파일을 삭제하거나 관련 미추적 파일을 추가함: `changed`.
- 작업 항목 사본을 얻지 못했거나 수집 도중 후보가 바뀜: 비교 결과 없음. 완전한 스냅샷을 확보합니다.
- 소스 파일은 같지만 실행 환경 식별값이 바뀜: `changed`. 기존 런타임 증거가 계속 유효한지 평가합니다.
