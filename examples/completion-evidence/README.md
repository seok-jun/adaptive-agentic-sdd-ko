# 완료 증거 보존

**OPTIONAL / FICTIONAL — 보존 절차를 설명하는 가상 예시이며 완료된 작업이나 실행한 검증이 아닙니다.** 아래 식별값은 모두 placeholder입니다. 생명주기와 허가는 [워크플로](../../docs/workflow.md)가 정의하며, 보존 시스템과 기간은 로컬 정책이 정합니다.

잘못된 입력을 거부하면서 정상 입력의 동작을 보존하는 Large 변경을 가정합니다. 가상 작업 항목에는 AC-01(거부)과 AC-02(기존 동작 보존)가 있습니다. 허가된 통합 후에는 임시 계획 메모를 정리할 예정입니다.

## 1. 승인된 설계 checkpoint 보존

기준 작업 항목 계약, AS-IS·PLAN 산출물, 단계별 독립 검토 기록, 해결한 지적사항, 필요한 설계 승인을 담거나 참조하는 불변 `<design-checkpoint>`를 보존합니다. 필요한 수준으로 검토자·승인자 식별값, 대상, 범위, 시간을 기록합니다. 설계 승인은 이후 병합을 허가하지 않습니다.

checkpoint는 보존된 커밋이나 버전이 있는 증거 저장소 기록일 수 있습니다. 임시 worktree나 보존 참조가 없는 로컬 커밋만으로는 보존을 보장할 수 없습니다. 예정된 정리 후에도 유지되는 참조와 저장 위치를 선택합니다.

## 2. 후보 요약과 증거 연결

[PR 템플릿](../../templates/pull-request.md)이나 동등한 기록을 사용합니다. `<final-commit>`에 연결할 요약은 다음과 같이 구성할 수 있습니다.

```text
작업 항목 계약: <item-revision>
승인 설계: <design-checkpoint> / <approval-record>
최종 후보: <final-commit>

AC-01: <actual status> / <candidate-environment> / <rejection-evidence>
AC-02: <actual status> / <candidate-environment> / <preservation-evidence>
검토: <phase-target-reviewer-verdict-records>
정정과 재실행: <history-reference>
잔여 위험: <비필수 제한, 사유, 담당자·후속 작업>
필수 차단 사항: <실제 증거로 확인한 경우에만 없음>

요청 행위: 이 후보 병합, 작업 항목 종료, 명시한 메모 정리
최종 허가: <candidate-action-approver-time-record>
보존 증거: <지속 저장 위치와 조회 참조>
정리 범위: <명시적인 이슈 전용 임시 경로>
```

이 placeholder는 PASS 결과가 아닙니다. 필수 FAIL·BLOCKED·UNVERIFIED나 검토 누락은 여전히 준비 완료를 차단하며, “잔여 위험” 아래에 옮겨 적어도 면제되지 않습니다. 이전 결과를 덮어쓰지 말고 기대값 정정과 승인된 범위 변경을 보존합니다.

요약은 증거 참조와 함께 커밋 메시지, PR, 버전이 있는 보고서에 둘 수 있습니다. 커밋 메시지에 남긴다면 그 메시지를 담은 커밋 자체가 식별값을 제공합니다. 아직 만들어지지 않은 자신의 해시를 메시지 안에 넣으려 하지 않습니다. 최종 커밋이 검토한 후보를 포함하는지 확인합니다. 이후 중요한 변경이 있으면 영향받는 검사·검토와 필요한 승인을 다시 확인합니다.

## 3. 허가 범위 안에서 통합하고 정리

필수 증거·검토와 최종 허가를 갖춘 뒤 허가된 통합을 수행합니다. squash나 rebase로 커밋 식별값이 달라지면 검토한 후보와의 관계를 포함해 실제 통합 리비전을 기록합니다. 내용이나 런타임 문맥이 달라졌다면 [검토 게이트](../../docs/review-gates.md)에 따라 재평가합니다.

임시 메모를 제거하기 전에 보존 참조를 열어 승인 설계, AC 관찰, 검토 결과, 정정 이력, 허가를 계속 조회할 수 있는지 확인합니다. 필요한 미추적·로컬 전용 증거는 작업 공간을 삭제하기 전에 승인된 보존 위치로 옮깁니다. 근거에 접근할 수 없는 요약이나 해시만으로는 충분하지 않습니다.

명시한 이슈 전용 산물만 제거합니다. 현행 동작 문서와 로컬 정책이 요구하는 증거를 보존하고 관련 없는 사용자·팀 변경은 그대로 둡니다. 정리가 검토한 소스나 실행·계약 문서를 바꾼다면 단순 정리로 취급하지 않고 후보 변경으로 처리합니다.

실제 통합·정리 결과는 앞서 작성한 후보 보고서와 구분해 기록합니다. 보존이나 정리가 해결되지 않았다면 완료한 행위와 남은 작업을 밝히고 생명주기 전체 완료를 주장하지 않습니다.

## 작은 작업에 적용할 때

작업 항목이나 PR 댓글에 후보, 필수 AC 관찰, 해당하는 검토·허가, 보존 증거 참조를 담을 수 있습니다. 이 예시는 Small·Trivial 작업에 별도 checkpoint 파일, Large 검토, 새 증거 서비스를 요구하지 않습니다.
