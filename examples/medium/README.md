# Medium 예시

**변경:** 두 구현 모듈에서 사용하는 새로운 공유 요청 필드를 추가합니다.

절차:

1. 이슈에서 경계와 계약의 의도를 정의합니다.
2. AS-IS에서 현재 계약과 직접 사용자를 확인합니다.
3. TO-BE에서 새 필드와 하위 호환 동작을 정의합니다.
4. 검증 전략에서 계약 동작을 단위·통합 테스트와 연결합니다.
5. 변경 계획에 구체적인 파일·심볼을 명시합니다.
6. 승인된 경계만 수정합니다.
7. 제한된 검토에서 계약 호환성과 diff 범위를 확인합니다.
8. 필수 테스트·검토 후 PR을 병합합니다.

구체적인 컴파일·의존성 실패로 영향 범위가 넓어지지 않는 한 저장소 전체를 다시 탐색할 필요는 없습니다.
