# Medium 예시

**가상 변경:** 하위 호환성을 유지하고 Large 수준의 실패 비용 없이 두 구현 모듈이 사용하는 공유 요청 필드를 추가합니다.

1. 작업 항목에 경계, 계약 의도, AC, 확정된 결정을 정의합니다.
2. AS-IS에 현재 계약과 직접 소비자를 기록합니다.
3. TO-BE, 보존할 호환성, 변경 계획의 파일·심볼을 정의합니다.
4. 구현 전에 AC를 기대 단위·통합 증거에 연결합니다.
5. 공유 계약 위험에 대해 범위를 제한한 독립 설계·계약 검토를 수행합니다.
6. 허가된 경계만 구현하고 대상·최종 AC 결과를 수집합니다.
7. 호환성, 증거, diff 범위에 대한 독립 CODE 검토를 받습니다.
8. 최종 후보를 제시하고 사람의 명시적 통합 허가를 받습니다.
9. 필수 증거·검토와 해당 허가를 충족한 뒤에만 병합합니다.

별도 섹션이면 충분합니다. 구체적인 의존성, 계약 충돌, 실패로 영향 범위가 넓어지지 않는 한 저장소 전체 재탐색은 필요하지 않습니다. 분석 중 Large 수준 위험이 드러나면 재분류합니다. 이는 진행 예시이지 검사·승인이 실제 발생했다는 증거가 아닙니다.
