# 트레이드오프 기록

실제로 서로 경쟁하는 선택지가 있을 때 트레이드오프 문서가 유용합니다.

프로세스가 에이전트에게 억지로 대안을 만들어 내도록 강제하면 오히려 낭비가 됩니다.

## 규칙

```text
IF 제한된 이슈 / AS-IS / 의존성 분석에서
   실제로 경쟁하는 선택지가 둘 이상 드러난다면
THEN 트레이드오프를 간단히 기록한다
ELSE 트레이드오프 섹션을 만들기 위한 추가 탐색은 하지 않는다
```

## 최소 형식

```md
## 트레이드오프

- 선택:
- 대안:
- 선택 이유:
- 감수한 비용:
```

선택 항목:

```md
- 재검토 조건:
```

구체적인 조건이 이미 존재할 때만 재검토 조건을 추가합니다.

## 피해야 할 것

- 대안을 찾기 위한 목적만으로 수행하는 저장소 전체 탐색
- 의무적인 브레인스토밍
- 일상적인 변경을 위한 다섯 가지 선택지 비교표
- 이슈 범위를 벗어난 추측성 아키텍처 재설계

## 목적

트레이드오프 기록은 **실제로 발생한** 결정을 보존합니다.

모든 작업을 설계 워크숍으로 만드는 구실이 아닙니다.
