# 핵심 개념

## 실행 명세로서의 이슈

이슈는 요청된 **TO-BE**를 규정합니다.

- 사용자 영향
- 목표
- 범위
- 허용·금지 경계
- 인수 조건
- 의존성과 차단 요소

이슈에 현재 구현을 완전히 기술하려고 해서는 안 됩니다. 현재 구현을 파악하는 일은 AS-IS 분석의 역할입니다.

## AS-IS와 TO-BE

다음과 같이 구분하면 유용합니다.

```text
현재 메인라인 코드 = 관찰된 AS-IS
현재 이슈          = 요청된 TO-BE
```

기능 개발 중에는 둘 사이에 차이가 있는 것이 자연스럽습니다.

오래된 문서와 현재 구현이 다르다는 이유만으로 코드를 “수정”하지 않습니다.

## 제한된 추론

구체적인 의존성, 컴파일 실패, 인수 조건 또는 충돌이 요구할 때만 에이전트가 컨텍스트를 확장해야 합니다.

목적은 어떤 대가를 치르더라도 사고를 최소화하는 것이 아니라, 일상적인 작업에서 끝없이 탐색하는 일을 피하는 것입니다.

## 증거

완료 여부는 변경에 적합한 증거로 뒷받침해야 합니다.

- 단위 테스트
- 통합 테스트
- 린트·정적 분석
- 빌드·패키징 검증
- CI
- 코드 검토
- 실기기·런타임 QA

“실행하지 않음”은 “통과”와 같지 않습니다.
