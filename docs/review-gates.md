# 검토 게이트

검토의 깊이는 위험에 따라 달라집니다.

## Small

기본 절차:

- 구현 에이전트의 자체 검토

구체적인 이유가 있다면 독립 검토를 선택적으로 적용할 수 있습니다.

## Medium

기본 절차:

- 제한된 검토를 적용할 수 있습니다.

검토자에게 제공하는 정보는 다음으로 좁혀야 합니다.

- 이슈
- 관련 AS-IS·TO-BE
- 변경 계획
- diff
- 검증 증거

검토자에게 제품 전체를 다시 탐색하도록 요청하지 않습니다.

## Large

다음 검토가 필요합니다.

1. **구현 전 설계 검토**
2. **병합 전 독립 코드 검토**

설계 검토에서는 다음을 확인합니다.

- 아키텍처·경계 위반
- 충족할 수 없는 인수 조건
- 안전하지 않은 실패 동작
- 명백히 누락된 통합 책임

코드 검토에서는 다음을 확인합니다.

- diff와 이슈의 일치 여부
- 검증 증거
- 회귀
- 범위 확장
- 안전하지 않은 구현 세부사항

## Epic

다음 검토가 필요합니다.

- 작업 분할 검토
- 위험한 하위 작업·통합 작업의 설계 검토
- 독립 코드 검토

## 검토는 해결책을 다시 탐색하는 과정이 아니다

검토자는 제안된 해결책을 주로 **반증**해야 합니다.

> 제안된 변경이 명백히 잘못되었거나 안전하지 않거나 범위를 벗어났거나 인수 조건을 충족할 수 없는가?

이렇게 하면 모든 검토가 또 하나의 저장소 전체 분석이 되는 일을 피하면서 독립 검토의 효용을 유지할 수 있습니다.
