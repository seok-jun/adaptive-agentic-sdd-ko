# 위험 등급

등급은 절차의 깊이를 결정하며, 비즈니스 우선순위를 뜻하지 않습니다.

## Small

일반적인 특성:

- 하나의 구현 경계
- 고위험 등급으로 자동 상향할 특성 없음
- 쉬운 로컬 검증

기본 절차:

- 이슈를 변경 계획으로 사용
- 별도의 SDD 문서 묶음 없음
- 대상 중심 테스트
- 자체 검토

## Medium

일반적인 특성:

- 여러 구현 경계
- 공유·공개 계약 변경
- 더 넓은 통합 범위
- 단, 영향이 큰 실패 형태는 없음

기본 절차:

- AS-IS
- TO-BE
- 변경 계획
- 검증 전략
- 유용한 경우 제한된 검토

## Large

다음과 같은 변경은 Large를 자동으로 고려합니다.

- 보안·개인정보 동작
- 영구 데이터 마이그레이션
- 재시도·스케줄링·백그라운드 정책
- 비용·쿼터·예산 집행
- 파괴적이거나 영향이 큰 복구 동작

기본 절차:

- 명시적 AS-IS 게이트
- TO-BE·변경 계획 게이트
- 구현 전 설계 검토
- 독립 코드 검토
- 안전성을 입증할 만큼 충분히 넓은 검증

## Epic

다음과 같은 경우에 사용합니다.

- 새 모듈 생성
- 의존성 방향 변경
- 독립적으로 전달할 수 있는 여러 기능의 결합
- 명시적인 통합 책임 필요

기본 절차:

- 구현 전 작업 분할
- 필요한 경우 통합 이슈·레인 지정
- 위험한 하위 작업에 Large 수준의 엄격성 적용

## 등급 인플레이션 방지

작업이 “중요하게 느껴진다”는 이유만으로 등급을 높이지 않습니다.

등급은 **변경 위험과 구현 범위**를 나타내야 합니다.

상위 등급의 게이트가 실제로 결함을 예방했는지 정기적으로 검토합니다.
