# 제한 환경의 검증 인계

**DRAFT / OPTIONAL — 제안 단계의 절차이며 구현되었거나 운영 검증을 마친 자동화가 아닙니다.**

에이전트가 DB나 통합 런타임에 직접 접근할 수 없는 환경을 위한 확장입니다. 기본 Skill 의존성이 아니며 접근 권한을 부여하거나 제한을 우회하거나 필수 검증을 대체하지 않습니다.

## 제안 흐름

```text
AC에 연결된 검증 계획
  -> 에이전트가 요청·쿼리 명세와 기대 관찰을 준비
  -> 허가된 실행자가 검토 후 승인된 환경에서 실행
  -> 비식별화된 증거 전달
  -> AC에 따라 결과 판정
```

준비와 실행은 별개입니다. 생성한 요청·쿼리는 적절한 실제 증거가 생기기 전까지 UNVERIFIED입니다. 구체적인 접근·환경 장애가 있으면 기존 상태 정의에 따라 BLOCKED로 기록합니다.

## 인계 자료

AC ID, 대상 후보·환경 식별값, 사전 조건, 기대 관찰, 허용 작업, 알려진 부작용, 실행 담당자, 안전한 결과 기록 형식을 포함합니다.

API 요청에는 method, endpoint placeholder, 입력, 인증 방식 placeholder, 기대 응답, 부작용을 명시합니다. 요청문을 생성했다는 이유만으로 자동 실행하지 않습니다.

DB 확인은 명시적으로 제공되고 승인된 스키마 계약만 사용합니다. 테이블·컬럼을 지어내지 않습니다. 좁은 조건, 적절한 결과 제한, 로컬 자원 보호 조건이 있는 검토된 읽기 전용 문장을 우선합니다. 읽기 전용이라고 비용이 없는 것은 아닙니다. 스키마 정보 누락은 미해결 입력이지 추측할 이유가 아닙니다. 변경 쿼리와 운영 환경 실행은 이 초안의 기본 범위 밖입니다.

`<approved_endpoint>`, `<approved_relation>`, `<sample_key>`는 명세용 placeholder이며 실행 가능한 fixture나 실제 인프라 식별자가 아닙니다.

## 증거와 안전

실행자는 기대 동작과 실제 동작, 후보·환경, 시간, 비식별화된 증거 참조를 기록합니다. 자격 증명, 연결 문자열, 실제 내부 endpoint, 운영 원본 행, 비공개 스키마, 민감한 응답을 공개 저장소에 올리지 않습니다.

[검증](verification.md)에 따라 증거를 판정합니다. 요청이 성공했다는 사실만으로 이후 DB 관련 AC 전체가 입증되지는 않습니다. 필수 증거 누락은 여전히 완료를 차단하며 사람의 승인이 PASS를 만들어내지 않습니다.

## 반환 관찰과 후속 처리

선택적 [검증 인계 양식](../templates/verification-handoff.md)은 준비한 계획, 실행자 관찰, 평가자 판정, 정정 이력을 분리합니다. 실행자에게 PASS 판정을 요구하지 않고 실제 값, 후보·환경·입력 식별값, 시각, 오류나 장애, 안전한 증거 참조를 받습니다. 실행자에게 기대값을 고치도록 요청하지 않고 원래 기대값을 계획과 함께 보존합니다.

1. 실행 전에 AC와 TC의 대응과 제안한 관찰이 AC를 입증할 수 있는지 확인합니다. 하나의 AC에 여러 TC가 필요할 수 있고, 하나의 TC가 여러 AC를 뒷받침할 수도 있습니다.
2. 결과를 받으면 대상 동일성과 증거의 충분성을 확인한 뒤 참조한 AC·계획 리비전에 따라 판정합니다. 불완전한 결과는 UNVERIFIED이며, 구체적인 장애 때문에 판정할 수 없으면 BLOCKED입니다.
3. 기대값에 이견이 있다면 [검증](verification.md)의 정정·요구사항 변경 구분을 적용합니다. 이전 증거와 결정을 보존합니다.
4. 코드를 수정한 뒤에는 관련 회귀를 포함해 영향받는 TC를 선정하고 재실행하며, 새 관찰을 새 후보에 연결합니다. 다른 증거를 재사용하는 이유도 기록합니다.

다음은 가상 판단 예시이며 실행 결과가 아닙니다.

| 상황 | 필요한 후속 처리 |
| --- | --- |
| AC는 “10 이상이면 거부”인데 TC가 10에서 허용을 기대함 | 변경되지 않은 AC를 근거로 TC를 정정하고 이전 기대값·관찰·판정을 보존한 뒤 증거가 충분한지 재평가합니다 |
| 결과를 본 뒤 원하는 규칙이 “10 초과면 거부”로 바뀜 | 필요한 범위·AC 결정을 받고 새 계약을 기록한 뒤 영향받는 검사·검토를 다시 확인합니다. 기대값만 조용히 고치지 않습니다 |
| 경계 동작을 고치기 위해 코드를 수정함 | 새 후보에서 경계값과 영향받는 회귀 TC를 다시 실행합니다 |
| 실행자가 승인된 환경에 접근할 수 없고 사용자가 TC 종료를 요청함 | 다른 유효한 증거를 제공하거나 범위·AC를 명시적으로 갱신하기 전까지 필수 AC의 차단 상태를 유지합니다 |

## 초안 이후로 승격하기 전에

허가된 가상·비식별 fixture로 파일럿을 수행합니다. 쿼리 안전성, 명확한 인계 책임, 재현 가능한 관찰, 정확한 상태 보고, 민감 출력 유출 방지를 확인합니다. 실제 관찰과 기대값을 따로 기록합니다. 그전까지는 배포된 기능이나 측정된 성공 사례가 아니라 제안 확장으로 설명합니다.
