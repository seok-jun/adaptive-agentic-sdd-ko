# 정보 유형별 Source of Truth(기준 출처)

Adaptive Agentic SDD는 모든 정보 유형에 하나의 전역 기준 출처를 적용하지 **않습니다**.

질문이 다르면 그에 대한 권위 있는 출처도 다릅니다.

| 정보 | 일반적인 기준 출처 |
| --- | --- |
| 현재 사용자의 지시 | 현재 사용자·세션 요청 |
| 목표·범위·인수 조건 | 현재 이슈 본문 |
| 에이전트 전체에 적용되는 가드레일 | 저장소의 에이전트 정책 |
| 워크플로·게이트 | canonical 워크플로·프로세스 정의 |
| 모듈 소유권·의존성 규칙 | 아키텍처 경계 문서 |
| 현재 동작(AS-IS) | 현재 메인라인 코드 |
| 구현 후 지속 관리되는 제품 규칙 | 최종 코드와 동기화한 제품·비즈니스 문서 |
| UI 레이아웃·상태 | 이슈에 연결된 시각 명세 |
| 과거 결정 근거 | 결정 기록·ADR |
| 임시 구현 계획 | SDD 작업 문서 |

## 하나의 SSOT를 사용하지 않는 이유

하나의 보편적인 출처만 권위 있는 것으로 정하면 레거시 시스템이나 계속 진화하는 시스템에서 모순이 생깁니다.

예를 들면 다음과 같습니다.

- **이슈**는 무엇이 변경되어야 하는지 설명합니다.
- **코드**는 현재 무엇이 일어나는지 설명합니다.
- **아키텍처 정책**은 넘을 수 없는 경계를 설명합니다.
- **시각 명세**는 UI 상태·레이아웃을 설명합니다.

각 정보 영역이 명확하다면 이들은 서로 경쟁하는 출처가 아닙니다.

## 충돌 처리

**같은 정보 범주** 안에서 두 출처가 충돌하고 그 충돌이 범위, 아키텍처 또는 인수 조건에 영향을 준다면, 구현 전에 멈추고 충돌을 해결합니다.
