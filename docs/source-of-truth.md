# 정보 유형별 Source of Truth

모든 정보 유형에 적용되는 전역 Source of Truth는 없습니다.

| 정보 | 일반적인 기준 출처 |
| --- | --- |
| 현재 사용자 지시·허가된 행위 | 적용되는 보호 규칙 안에서 현재 사용자가 명시적으로 요청한 내용 |
| 목표·범위·AC | 현재 작업 항목 또는 신뢰할 수 있는 버전 스냅샷 |
| 전역 에이전트 보호 규칙 | 저장소 루트 에이전트 정책 |
| 생명주기·게이트 | 기준 워크플로와 검토·검증 정의 |
| 등급 의미·깊이 | 위험 등급표 또는 명시적으로 도입한 로컬 계약 |
| 모듈 소유권·의존 규칙 | 아키텍처 경계 문서 |
| 현재 동작(AS-IS) | 현재 메인라인 코드와 직접 런타임 증거 |
| 지속적인 제품 규칙 | 최종 동작에 맞춰 동기화한 제품·업무 문서 |
| UI 배치·상태 | 작업 항목에 연결된 시각 명세 |
| 과거 결정 배경 | 결정 기록·ADR |
| 임시 구현 계획 | 현재 SDD 작업 문서 |
| 검증 결과 | 실제 리비전·환경에 대한 AC 연결 실행·관찰 기록 |
| 검토 결과 | 대상 단계·리비전의 검토 기록 |
| 사람의 승인·통합 권한 | 대상 리비전과 행위 범위에 대한 명시적 승인 또는 적용 가능한 위임 기록 |

작업 항목은 무엇을 바꿀지, 코드는 현재 구현을, 아키텍처는 허용 경계를, 검토 기록은 특정 후보의 판정을 설명합니다. 서로 다른 질문에 답하는 출처입니다.

## 충돌 처리

같은 정보 유형의 충돌이 범위, 아키텍처, AC, 승인, 지속적인 계약 의미에 영향을 주면 구현 전에 해결합니다. 코드는 현재 동작의 증거이지 요구사항을 덮어쓸 권한이 아닙니다. 사용자 요청이 보호 규칙을 조용히 폐기하는 것도 아닙니다.

오래된 티켓 복사본, 과거 댓글·계획·검토 판정으로 현재 기준을 덮어쓰지 않습니다. 실시간 접근이 불가능하면 스냅샷의 리비전 경계를 식별합니다.

## 한 곳에서 정의하고 다른 곳에서 참조

개발자 가이드·도식·예시는 기준 정책을 설명하며 다시 정의하지 않습니다. 루트 지침은 Skill로 연결하며, 하나의 게이트를 여러 곳에서 독립적으로 정의·관리하지 않습니다.

starter의 로컬 계약은 의도적으로 자체 완결적인 도입 스냅샷입니다. 도입 이후 해당 저장소가 로컬 정책을 소유하며, 업그레이드를 명시적으로 조정해야 합니다. 공개 저장소의 향후 변경을 자동으로 상속하지 않습니다.
