# 토큰·컨텍스트 효율

Adaptive Agentic SDD는 컨텍스트·추론 비용을 엔지니어링 제약조건으로 취급합니다.

## 원칙

### 1. 직접 관련된 내용만 읽는다

기본적으로 관련 없는 이슈나 도메인, 과거 검토 내용을 불러오지 않으며, 경계에 관한 질문이 없다면 광범위한 아키텍처 문서도 읽지 않습니다.

### 2. 좁은 범위에서 시작한다

다음 순서를 사용합니다.

```text
이슈
-> 직접 경로
-> 직접 심볼
-> 공개 계약
-> 직접 호출자·피호출자
-> 구체적인 증거가 요구할 때만 범위 확장
```

### 3. 같은 실행 안에서는 컨텍스트를 재사용한다

변경되지 않은 이슈 본문, 프로세스 규칙, 소스 파일 또는 환경 확인 결과를 다시 읽지 않습니다.

### 4. 확정된 요구사항을 다시 탐색하지 않는다

이슈에서 요구사항을 명시적으로 결정했다면, 충돌이 나타나지 않는 한 구현 에이전트가 제품 탐색을 반복해서는 안 됩니다.

### 5. 대상 중심 검증을 먼저 수행한다

개발 중에는 유용한 최소 범위의 검사를 실행합니다. 비용이 큰 광범위한 검사는 적절한 완료 게이트에서 실행합니다.

### 6. 검토·QA에서 다시 설계하지 않는다

독립 에이전트는 제한된 증거 묶음을 전달받아 정확성을 확인해야 하며, 제품 탐색을 처음부터 다시 시작해서는 안 됩니다.

## 적응형 추론 예산

```text
Small  = 간결
Medium = 표준
Large  = 심층
Epic   = 작업 분할 + 심층 + 독립 검토
```

목표는 어떤 대가를 치르더라도 토큰 사용량을 줄이는 것이 아닙니다. 목표는 **실패 비용이 큰 곳에 추론 자원을 사용하는 것**입니다.
