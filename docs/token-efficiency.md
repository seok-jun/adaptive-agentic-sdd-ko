# 토큰·컨텍스트 효율

컨텍스트는 예산이지 성실함의 증거가 아닙니다.

## 점진적 공개

```text
작은 루트 계약 -> 작업 라우터 -> 작업 Skill -> 조건부 절차·도메인 문서
```

항상 적용하는 보호 규칙, 라우팅, 안정적인 불변 조건만 루트에 둡니다. 반복 절차는 Skill·절차 문서에 둡니다. 같은 설명의 복사본 여러 개 대신 하나의 기준 정의를 읽습니다.

## 기본 읽기 순서

- 관련 없는 백로그보다 현재 작업 항목을 먼저 읽습니다.
- 직접 경로·심볼, 선언과 판단에 필요한 주변 줄, 직접 계약·호출자·피호출자 순으로 확인합니다.
- 실제 경로나 결정에 필요할 때 도메인·아키텍처 규칙을 읽습니다.
- 전체 diff 전에 변경 파일 목록과 관련 hunk를 확인합니다.
- 변경되지 않은 문맥을 재사용하고 성공 로그는 요약하되 실패·불확실성은 상세히 확인합니다.
- 전체 검사보다 대상 검사를 먼저 실행하고, 확정된 요구사항을 재탐색하거나 불필요한 대안 탐색을 만들지 않습니다.

## 에이전트 인계 예산

작업, 단계, 대상 리비전, AC 참조, 허가된 수정 경계, 확정된 결정, 직접 증거, 알려진 미확인 사항을 전달합니다. 부모의 전체 대화나 관련 없는 이력을 기본으로 제공하지 않습니다.

간결한 판정·결과, 구체적인 지적사항, 증거 위치, 변경 범위, 미검증·차단 사항을 반환합니다. 원본 증거는 접근 가능하게 유지합니다. 요약이 불확실성을 숨기거나 감사를 막아서는 안 됩니다.

Blind Audit에는 최초 결과 확정 전 주 검토의 판정·지적사항을 전달하지 않습니다. AC나 안전 경계를 누락하지 않습니다. [검토 게이트](review-gates.md)를 참고하세요.

## 재사용과 확장

작업 항목, 규칙, 소스 발췌, 검증 문맥은 버전과 관련성이 유지되는 동안에만 재사용합니다. 요구사항, 산출물, 범위, 적용 규칙이 바뀌면 영향받는 부분을 다시 읽고 의존하는 게이트를 재확인합니다. 이전 세션 요약은 현재 상태의 증거가 아닙니다.

탐색을 넓히는 구체적인 이유를 기록합니다. 예를 들어 호출자가 주장된 불변 조건과 충돌할 수 있습니다. **수정** 허용·금지 경계는 직접 의존 관계를 읽지 말라는 뜻이 아닙니다. 더 넓은 읽기가 더 넓은 수정 권한을 주지는 않습니다.

공통 토큰 상한이나 provider·모델별 표를 공개 코어에 넣지 않습니다. 측정하지 않은 절감 효과를 주장하지 않고 실제 사용을 관찰해 로컬 예산을 조정합니다.

## 증거를 줄이는 최적화 금지

토큰 절약을 위해 필수 최초 읽기, 범위·등급 게이트, 독립 검토, 검증, 필요한 런타임 QA, 사람의 허가, 완료 증거를 제거하지 않습니다. 줄일 것은 관련 없는 문맥이지 입증이 아닙니다.

빌드 도구, shell, encoding, 기기, 환경, 모델 라우팅 예외는 로컬에 둡니다.
