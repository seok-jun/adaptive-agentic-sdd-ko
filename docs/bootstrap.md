# 기존 저장소에 Adaptive Agentic SDD 도입하기

점진적으로 도입합니다. 성숙한 프로젝트의 전체 워크플로를 첫날부터 가져오지 않습니다.

## 1단계 — 수정 전에 관찰

저장소·모듈 구조, 실제 빌드·테스트 진입점, CI·릴리스 기능, 작업 관리 시스템, 기존 규칙, 아키텍처 경계, 지속 문서, 생성·vendor·공유 경로를 분석합니다.

관찰 사실과 제안 규칙을 구분합니다. CI, DB 연결, 독립 에이전트 기능이 없는 것은 사용 가능한 기능의 제약이지 성공한 검사를 지어낼 권한이 아닙니다.

## 2단계 — 간결한 루트 계약

작업 항목 식별 방법, 항상 적용할 안전·범위 보호 규칙, 작업 라우팅, 확인된 명령 참조, 안정적인 불변 조건을 `AGENTS.md`에 둡니다. 모든 절차를 넣지 않습니다.

[starter/AGENTS.md](../starter/AGENTS.md)는 그대로 복사할 설정이 아니라 구조 예시로 사용합니다.

## 3단계 — 구현 Skill 하나 추가

하나의 기준 실행 경로로 시작합니다.

```text
작업 항목 -> 사전 점검 -> 등급 -> 제한된 분석 -> 계획
  -> 구현 -> 검증 -> 검토 -> 최종 허가 -> 허가된 마무리
```

starter는 함께 동작하는 세 파일로 구성됩니다. `starter/AGENTS.md`를 저장소 루트에, `starter/.agents/skills/implementing-issue/SKILL.md`를 해당 로컬 Skill 경로에, `starter/docs/sdd-workflow.md`를 로컬 `docs/sdd-workflow.md`에 맞춰 도입합니다. 기존 파일을 덮어쓰지 말고 조정·통합합니다.

로컬 계약은 자체 완결적으로 도입된 게이트의 의미를 소유합니다. 공개 저장소가 자동으로 로드되는 의존성은 아닙니다. 반복 사용으로 문맥 절감이나 모호성 해소가 확인될 때만 Skill을 더 나눕니다.

## 4단계 — 등급·검토·허가

[위험 등급](risk-grades.md)의 Trivial, Small, Medium, Large와 분할이 필요한 경우 Epic을 사용합니다. story point만이 아니라 실패 비용, 가역성, 계약 영향 범위, 조정 위험으로 분류합니다.

저위험 작업의 분석·기록은 간결하게 유지합니다. Large에는 AS-IS와 PLAN의 독립 검토 판정이 각각 있습니다. 별도 Reviewer를 어떻게 확보할지 정하고, 확보하지 못하면 필수 독립 검토를 완료했다고 주장하지 않습니다.

설계 승인과 최종 통합 권한을 구분합니다. 기본값은 사람의 명시적 최종 승인입니다. 저위험 통합 위임에는 문서화된 범위·적용 조건이 있어야 합니다. 증거·승인을 대상 리비전에 연결합니다.

## 5단계 — 실제 작업 관리 시스템 연결

GitHub Issue는 필수가 아닙니다. 현재 작업 항목이나 신뢰할 수 있는 스냅샷에 목표, 사용자·업무 영향, 범위·제외 범위, AC, 확정된 결정, 차단 사항, 등급, 수정 경계, 관련 명세가 있어야 합니다.

실시간 접근이 불가능하면 스냅샷 식별자·리비전을 명시합니다. 오래된 복사본을 조용히 현재 기준으로 취급하지 않습니다.

## 6단계 — 좁은 작업으로 파일럿

Large 마이그레이션 전에 Trivial·Small 작업을 시도합니다. 에이전트가 관련 없는 파일을 읽는지, 로컬 규칙을 놓치는지, 범위 밖을 수정하는지, 설정을 반복하는지, 미실행 검사를 잘못 표시하는지, 권한 없이 완료를 주장하는지 관찰합니다.

일상 요청과 기대 출력은 [개발자 가이드](developer-guide.md)를 참고합니다. 실제 실행과 예시의 기대 동작을 따로 기록합니다. 가정상의 완전함이 아니라 관찰된 실패를 바탕으로 조정합니다.

## 7단계 — 필요한 심층 게이트만 추가

간결한 경로가 동작한 뒤 Medium·Large 분석, 단계별 검토, 사람이 소유한 설계 결정 승인, 독립 CODE 검토, 누락·편향 위험의 선택적 Blind Audit, 조건부 런타임 QA를 추가합니다. 모든 작업을 가장 깊은 경로로 보내지 않습니다.

## 공개 코어와 로컬 보호 규칙

실제 모듈·경로 소유권, 제품 용어, 자격 증명, 모델 라우팅, 승인 시스템 연동, 빌드·shell·encoding 우회 처리, 기기 설정은 로컬에 둡니다. 공개 예시는 가상 사례이며 비공개 구현 세부 사항과 독립적이어야 합니다.

[제한 환경 검증 초안](restricted-environment-verification.md)은 선택 사항이며 검증된 자동화가 아닙니다. 허가된 파일럿 이후 도입하고 모든 Skill 실행에 조용히 추가하지 않습니다.

## 최초 요청 예시

```text
제품 코드를 수정하지 말고 이 저장소를 분석해 주세요.
실제 구조, 경계, 빌드·테스트·CI 기능, 작업 관리 시스템,
기존 규칙, 지속 문서, 고위험 공유 경로를 확인해 주세요.
최소한의 도입안을 제안하고 공개 규칙과 로컬 규칙을 나눠 주세요.
루트 지침, 작업 Skill, 조건부 문서에 어디까지 둘지 설명하고,
사용할 수 없는 기능과 사람이 결정해야 할 사항을 명시해 주세요.
```
