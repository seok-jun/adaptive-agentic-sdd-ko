# 검증 전략

단순하지 않은 작업에서는 구현 전에 검증을 설계해야 합니다.

## 목표

중요한 모든 인수 조건에는 실행 가능한 입증 방법이 있어야 합니다.

예시:

| 인수 조건 | 증거 |
| --- | --- |
| 파서가 잘못된 입력을 거부함 | 단위 테스트 |
| 계약이 두 모듈을 통해 연결됨 | 통합 테스트 |
| 애플리케이션이 계속 패키징됨 | 빌드 |
| UI 상태가 시각적으로 올바름 | 실기기·UI QA |
| 백그라운드 작업이 생명주기 전반에서 올바르게 동작함 | 실기기·런타임 QA |

## 규칙

- 인수 조건을 신뢰성 있게 입증할 수 있는 가장 저렴한 증거를 사용합니다.
- 관련 내용이 바뀌지 않았다면 비용이 큰 광범위한 검사를 반복 실행하지 않습니다.
- 실행하지 않은 검사를 통과했다고 주장하지 않습니다.
- 허용된 범위 안에서 인수 조건을 입증할 수 없다면 이슈를 차단 상태로 처리하거나 범위를 명시적으로 수정합니다.

## 대상 중심 검증 우선

다음 순서를 권장합니다.

```text
대상 중심 테스트
  -> 영향받은 모듈 테스트
  -> 필요한 경우에만 더 광범위한 테스트·린트·빌드
```

이렇게 하면 피드백 속도를 유지하면서 위험한 작업에 더 강한 게이트를 적용할 수 있습니다.
