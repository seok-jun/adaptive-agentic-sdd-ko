# 개발자 실행 가이드

도입은 [도입 가이드](bootstrap.md)에서 시작합니다. 정책은 [워크플로](workflow.md), [위험 등급](risk-grades.md), [검토 게이트](review-gates.md), [검증](verification.md)을 따릅니다. 이 문서는 일상 사용법을 설명하며 새 필수 게이트를 추가하지 않습니다.

## 1. 범위를 제한한 계획 요청

```text
현재 작업 항목 <참조/리비전>과 저장소 규칙을 읽어 주세요.
아직 파일을 수정하지 마세요. 등급과 근거, 목표, AC,
수정 허용·금지 범위, 미확인 사항, 검증 방법,
필요한 검토·승인 게이트를 제시해 주세요.
충분한 수준에서 가장 작은 계획을 제안해 주세요.
```

기대 출력은 관찰 사실과 가정·제안이 분리된 결과입니다. 작업 관리 시스템에 접근할 수 없다면 리비전 경계가 있는 허가된 최신 스냅샷을 제공합니다. 민감한 자료를 공개 작업 항목에 붙이지 않습니다.

## 2. 계획 검토와 구현 허가

범위, 보존할 동작, 실패 처리, AC 입증 가능성을 확인합니다. Large에는 AS-IS와 PLAN의 검토 판정이 각각 있어야 합니다. 무엇을 검토했는지 불분명한 설계 PASS 하나로는 충분하지 않습니다.

```text
PLAN <리비전>의 <범위>에 대한 구현을 승인합니다.
<경계>는 변경하지 마세요. 필요한 경우 <작업 브랜치>에만 커밋하세요.
병합, 작업 항목 종료, 릴리스는 하지 마세요.
중요한 범위 변경이 필요하면 멈추세요.
```

이는 구현 허가이지 앞으로의 모든 작업에 대한 포괄 승인이 아닙니다. placeholder를 실제 저장소 사실로 바꾸고 명령·경로·승인 기록을 지어내지 않습니다.

## 3. 후보 보고서 읽기

최종 리비전, 변경 범위, AC별 실제 결과, 필요한 검토 기록, 문서 동기화, 남은 위험, 요청하는 다음 행위를 확인합니다.

PASS에는 실행한 검사 또는 적절한 직접 관찰 근거가 있어야 합니다. 생성한 명령과 제안한 기대값은 런타임 증거가 아닙니다. 필수 독립 검토는 별도의 에이전트 호출·사람이 수행해야 하며 자체 검토는 자체 검토라고 표시해야 합니다.

Trivial·Small은 별도 SDD 보고서 대신 작업 항목·PR의 몇 줄로 기록할 수 있습니다. 에이전트 실행 규칙에 영향을 주는 문서 변경은 자동으로 Trivial이 되지 않습니다.

## 4. 범위를 조용히 넓히지 않고 중단·재개

| 상황 | 처리 |
| --- | --- |
| 범위 밖 수정이 필요함 | 해당 수정을 멈추고 명시적 경계 갱신을 요청 |
| 실패 비용이 큰 새 위험 발견 | 재분류하고 영향받는 게이트 재확인 |
| 필요한 환경·권한 없음 | 사유와 함께 BLOCKED 기록, PASS로 표시하지 않음 |
| 검사를 실행하지 않음 | UNVERIFIED와 부족한 증거 기록 |
| 독립 Reviewer를 확보하지 못함 | 필수 검토를 미충족으로 남기고 다른 검토자 확보 |
| 검토·승인 후 중요한 변경 발생 | 영향받는 증거 재검사, 재검토, 필요한 새 승인 요청 |

후보·작업 항목 리비전과 차단 사항의 해결을 명시한 뒤 재개합니다. 변경되지 않은 증거도 여전히 관련 있을 때만 재사용합니다.

## 5. 최종 Human Review와 허가

```text
후보 <리비전>을 최종 Human Review에 제출해 주세요.
AC 결과, 필수 검토 증거, 문서 동기화, 제한 사항,
정확히 요청하는 통합 행위를 포함해 주세요. 아직 병합하지 마세요.
```

필수 증거·검토를 충족한 다음 승인합니다.

```text
후보 <리비전>을 <대상 브랜치>에 병합하는 것을 승인합니다.
<작업 항목 종료와 릴리스의 포함·제외 여부를 명시합니다.>
```

필수 AC가 FAIL·BLOCKED·UNVERIFIED인 상태에서는 이 승인을 주지 않습니다. 적용 가능한 저위험 사전 통합 허가는 문서화된 로컬 정책 예외이지 에이전트의 추정이 아닙니다.

## 가벼운 경로 선택

작업 시간이 아니라 [기준 등급표](risk-grades.md)를 사용합니다. 오탈자는 Trivial, 좁은 동작 수정은 Small, 실패 비용이 낮은 공유 계약 변경은 Medium, 인가 변경 한 줄은 Large일 수 있습니다. Epic은 하위 구현 전에 분할합니다.

[Trivial](../examples/trivial/README.md), [Small](../examples/small/README.md), [Medium](../examples/medium/README.md), [Large](../examples/large/README.md) 예시를 참고하세요. 가상 진행 예시이며 실행 증거가 아닙니다.

## 제한 환경 — 선택적 초안

[API·DB 검증 인계 초안](restricted-environment-verification.md)은 산출물 준비, 허가된 실행, 판정의 분리를 제안합니다. DB 연결을 추가하거나 운영 검증을 주장하지 않습니다. 관련 없는 작업에서 읽지 않습니다.
